Write CSS the next dev can read.

Good CSS is a series of small refusals: no selectors longer than they need to be, no nesting deeper than it must go, no declaration written twice, no magic number left unexplained — and a mobile-first base that only ever adds. Five habits that keep a codebase fast to change.

01 · avoid unnecessary selectors

Long selectors are fragile

.box ul li a and .link hit the same element today. But the long one encodes the whole DOM path — restructure the HTML and it silently breaks. The class survives.

              Every extra combinator is a promise about markup you may not
              control. Select the thing, not its ancestry.
            

          

        

      


      
      

        

          
02 · avoid excessive nesting

          
Depth is specificity is pain

          

            Each nesting level adds a class to the compiled selector — and to
            its specificity. Drag the depth and watch the tuple climb: deep
            rules are hard to override and hard to find.

03 · reuse styles

          
Write it once, use it everywhere

          

            Three identical cards. In shared mode one rule styles all — a
            brand change is one edit. In duplicated mode each has its own
            copy — the same change needs three edits and they drift. Pick a
            color and feel it.

05 · mobile-first approach

          
Base small, then enhance

          

            Write the mobile layout as the base, then layer
            min-width queries that only add.
            Drag the width and watch layers stack — no un-setting, no overrides,
            easier to reason about.
