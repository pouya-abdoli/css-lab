lesson 37 · interactive

CSS that scales past you.

Small files are easy; big codebases are where CSS goes to die — global selectors leak, names collide, specificity spirals. Architecture is the discipline that prevents it: name by purpose, build components, scope what must be scoped, and keep utilities for the one-offs.

02 · BEM

          
Block __ Element -- Modifier

          

            A naming grammar that reads like the DOM: the Block is the
            component, the Element is a part of it, the
            Modifier is a variant. Pick a part and a variant — the class
            string builds itself.

03 · component-based CSS

          
One source, every instance

          

            A component owns its styles; every instance is identical by
            construction. Edit the component's custom properties and all three
            placements — nav, hero, footer — update together. No per-context
            overrides.

04 · utility classes

          
Single-purpose, composable

          

            Utilities do one thing (.text-center,
            .mt-4) and compose in the markup. Perfect
            for one-offs that don't deserve a component. Toggle them and watch
            the class list build.

              Rule of thumb: components for repeated patterns,
              utilities for layout glue and one-offs. Most codebases want
              both, in balance.
            

          

        

      


      
      

        

          
05 · CSS modules

          
Scope at build time

          

            Two components both define .title. Without
            scoping, a global .title rule hits both
            (collision). CSS Modules hash each name per file, so they can't
            collide. Toggle scoping and watch.
